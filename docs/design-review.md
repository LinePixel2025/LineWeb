# Line Web 前端设计评审与改进建议

基于 frontend-design skill 框架，对现有 Liquid Glass 设计系统进行结构化评审。

---

## 1. 总体印象

**当前状态**：高完成度的 Apple Liquid Glass 复现——SVG 折射滤镜、交互式镜面高光、色差边缘、自动壁纸对比度系统，技术执行扎实。但整体给人的阅读体验接近"Apple 设计系统克隆"，缺乏这个项目本应拥有的独特身份。

**核心问题**：设计系统在"像 Apple"这件事上做得很好，但"作为一个个人的、有观点的网站"这件事上还不够。字体、色彩、布局都选择了最安全的默认值，没有留下属于 Line Web 自己的视觉印记。

---

## 2. 字体 — 最优先的改进项

### 现状
```
--lg-font: -apple-system, BlinkMacSystemFont, 'SF Pro Display', 'SF Pro Text', ...
--lg-font-mono: 'SF Mono', 'Fira Code', 'JetBrains Mono', ...
```
纯系统字体栈。SF Pro 在 Apple 平台上表现优秀，但正因如此，它让整个网站读起来像"任何 Apple 风格网站"——没有可辨识度。

### 建议

**引入一个具有性格的展示字体用于标题**，与 SF Pro Text 保持身体文字。这是投入产出比最高的改变——一个字体就能建立 50% 的视觉身份。

推荐的配对方向（选择一个）：

| 方向 | 展示字体（标题） | 搭配理由 |
|------|-----------------|----------|
| **温暖人文** | Instrument Serif 或 Newsreader | 衬线体与玻璃的科技感形成张力，增加温暖的个人感 |
| **几何精准** | ABCDiatype 或 GT America Expanded | 大写标题用宽体字距，与玻璃的精密感一致 |
| **低调个性** | Departure Mono 等宽 | 小字号等宽标题 + 正常正文，建立极客/开发者的诚实感 |
| **中式融合** | ZCOOL QingKe HuangYou + Noto Sans SC | 对中文更好的支持，在个人博客语境下有本土感 |

**实施要点**：
- 只用于 h1-h3 标题，保持克制
- 保留 SF Pro Text 作为正文，确保长文阅读体验
- heading 字重从现在的 600 考虑是否可以用更轻（400-500）或更重（700-800）来匹配所选字体

## 3. 色彩 — 引入一个意外的强调色

### 现状
```
--lg-accent: #2997ff        /* Apple 默认蓝 */
--lg-danger: #ff3b30        /* Apple 系统红 */
--lg-success: #34c759       /* Apple 系统绿 */
--lg-warning: #ff9500       /* Apple 系统橙 */
```
完全复用了 Apple HIG 的语义色。安全，但无记忆点。

### 建议

**主强调色不变（蓝色是 Glass 美学的基础），但引入第二个"签名色"用于点缀和交互反馈**。

推荐的签名色方向：

- **暖珊瑚** `#E8927C` 或 `#D4786A` — 与冷色调玻璃形成互补，适合用作 hover 态、Logo、特别 badge
- **金琥珀** `#C9A96E` — 低调的金属感，与玻璃的反射质感呼应
- **暗紫罗兰** `#8B7EC8` — 科技感 + 个人化，替代蓝色用于特定交互元素

**实施建议**：
- 新增 `--lg-accent-secondary` 变量
- 在 Logo、特殊状态标签、部分 hover 态中使用
- 保持蓝色为主色，签名色使用率不超过 10%

## 4. 间距与网格 — 定义正式的垂直节奏

### 现状
间距是 ad-hoc 的——`marginTop: '36px'`、`padding: '48px'`、`gap: '14px'` 等散落在各处，没有统一的节奏系统。

### 建议

基于 8px 网格定义间距 scale，增加到变量文件中：

```css
--lg-space-1: 4px;
--lg-space-2: 8px;
--lg-space-3: 12px;
--lg-space-4: 16px;
--lg-space-5: 24px;
--lg-space-6: 32px;
--lg-space-7: 48px;
--lg-space-8: 64px;
--lg-space-9: 96px;
```

然后系统性地替换内联样式中的硬编码间距值。这将带来：
- 所有 section 之间的一致间距
- 卡片内外边距的稳定比例
- 响应式断点处只需调整个别 token 值即可全局生效

**优先整改区域**：HomePage、FeaturesPage、PostsPage 的内联 padding/margin。

## 5. Hero 区 — 从"卡片"变为"场景"

### 现状
```
┌────────────────────┐
│    Line Web        │  ← 小号居中卡片，max-width 520px
│  [按钮] [按钮]     │
└────────────────────┘
```
Hero 区是目前最大的"未充分利用"空间——整个视口高度（100dvh）只放了一张 520px 宽的卡片，内容只有标题和两个按钮。这个空间本可以传达更多关于"Line Web 是谁"的信息。

### 建议

**方向 A — 叙事型 Hero**：保留卡片但加入副标题和一句话身份声明。
```
┌────────────────────────────────────┐
│  ┌──────────────────┐              │
│  │  Line Web        │  ← 放大标题  │
│  │  一个关于 [X] 的  │  ← 真实身份  │
│  │  个人空间         │              │
│  │  [浏览文章] [关于]│              │
│  └──────────────────┘              │
│    live wallpaper background       │
└────────────────────────────────────┘
```
"一个关于 _____ 的个人空间"这句话应该反映这个网站的真实主题（技术？写作？设计？）。模糊的文案 = 模糊的设计。

**方向 B — 沉浸式 Hero**：利用玻璃折射制造动态背景效果——比如在 Hero 背景层放一个慢速旋转的 3D 几何体或动态粒子，通过玻璃折射呈现。让 glass 效果本身成为 showpiece。

> 选择建议：方向 A 成本最低、收益最确定。方向 B 需要额外的前端工作。**当前阶段选 A，文案定下来后可以逐版迭代。**

## 6. 动效 — 从"有"到"有意义"

### 现状
- 页面加载：`fadeIn`（透明度 + 位移 10px）
- 卡片入场：`glassRise`（透明度 + 位移 16px + scale 0.97）
- 交错的渐入：`animationDelay: ${i * 0.08}s`
- Hover：`scale(1.02)` / `translateY(-1px)`

这些动画存在但不构成记忆点。

### 建议

1. **Scroll-triggered reveals**：用 Intersection Observer 替代基于类名的入场动画，让内容在滚动到视口时才出现。这比所有元素同时渐入更有节奏感。

2. **玻璃折射微动效**：.lg-surface hover 时，微调 `feDisplacementMap` 的 scale 值（通过 CSS 变量或 class 切换），让折射在交互时产生"波动"效果——这个细节如果真的实现，会成为最独特的记忆点。

3. **导航栏背景变化**：滚动时导航栏的玻璃透明度/模糊度渐变。当前是固定样式，滚动后可以略微加深背景（从 `rgba(255,255,255,0.07)` 过渡到 `rgba(255,255,255,0.12)`），增强滚动时的层级感。

4. **页面切换过渡**：当前路由切换无过渡。可以在 Layout 层添加 `fadeIn` 动画到 `<Outlet>`，消除突兀的闪现。

## 7. 内容层次 — 区分"首页"和"管理后台"

### 现状
当前两个环境共享同一套设计 tokens——这在视觉一致性上是好事，但管理后台因此缺乏操作界面的"效率感"。

### 建议

管理后台可以考虑微调：
- 表格行更紧凑（当前 padding 12px 16px 偏大）
- 减少玻璃效果用量；后台更需要"清晰"而非"漂亮"
- 增加内容密度：后台页面在 1440px 宽屏上内容区 `max-width: 900px` 过于居中，考虑放宽到 `max-width: 1200px`

## 8. 亮色模式 — 缺失的主题

### 现状
系统描述中声明支持亮色/暗色/跟随系统三种模式，但代码中 `:root` 只有暗色变量，亮色变量未定义。这会导致系统在亮色模式下完全不可用。

### 建议

如果亮色模式是计划中的功能，需要：
1. 定义 `[data-theme="light"]` 下的完整色彩 token
2. 在 CSS 中为亮色模式单独指定玻璃效果参数（浅色背景上毛玻璃需要不同的透明度和阴影）
3. 在 Navbar 或 Profile 页添加切换入口

如果亮色模式已被放弃但从文档中移除，应更新 AGENTS.md 避免混淆。

## 9. 微交互与细节

### 小改进（低投入，高感知）

| 位置 | 当前 | 建议 |
|------|------|------|
| Logo | 纯文本 "Line Web" | 可以考虑增加一个简单的 SVG 图形标记，在导航栏和管理侧边栏复用 |
| Navbar 链接 | 悬停变蓝底 | 激活页面的指示器可以增加一个底部小圆点或下划线动画 |
| Loading | 旋转 spinner | 可以考虑用玻璃材质的 skeleton + 脉冲光效替代 |
| 404 页 | 未检查 | 需要有 404 页面，利用玻璃效果做一个"消失"的视觉概念 |
| 文章卡片 | 统一的 lg-surface-blur | 最新文章可以考虑用更透的玻璃层级，区分"特色"和"普通" |
| 空状态 | 文字提示 | Features 和 Drive 的空状态可以用插画风的大 emoji + 引导文案 |
| 按钮过渡 | 0.25s cubic-bezier | 所有交互元素统一使用相同的缓动曲线（当前部分用了 0.2s ease 不一致） |

## 10. 优先级排序

| 层级 | 改进项 | 预估投入 | 影响面 |
|------|--------|---------|--------|
| **P0** | 字体系统 — 引入展示字体 + 定义字重/字距 | 低 | 全局视觉身份 |
| **P0** | Hero 区文案 | 低 | 首页第一印象 |
| **P1** | 色彩签名色 | 低 | 品牌记忆点 |
| **P1** | 间距 token 化 | 中 | 全局一致性和维护性 |
| **P1** | 亮色模式（确认状态） | 高 | 用户覆盖 |
| **P2** | Scroll-triggered reveal | 中 | 浏览体验 |
| **P2** | 导航栏滚动动效 | 低 | 交互质感 |
| **P2** | 页面切换过渡 | 低 | 导航流畅度 |
| **P3** | 管理后台紧凑化 | 中 | 操作效率 |
| **P3** | 404/空状态页面 | 低 | 完整度 |
| **P3** | 玻璃折射微动效 | 高 | 独特性 |

---

## 总结

Line Web 拥有一个技术上令人印象深刻的设计系统。改进的关键不在于增加更多效果，而在于**做减法后的聚焦和个性化**。

三个"如果只能选三件事"的推荐：
1. **换掉纯系统字体** — 单这一项改变就能让网站看起来有观点
2. **用一句话定义 Hero 区文案** — 让"Line Web"不再只是一个名字
3. **引入一个暖调签名色** — 在冷色调玻璃海洋中留一个温度锚点
